# Платежи gremu

## Как устроено

- `src/features/payments/types.ts` — интерфейс `PaymentProvider` и статусы оплаты заказа:
  `unpaid → pending → paid`, а также `failed`, `cancelled`, `refunded`.
- `src/features/payments/payme/` — адаптер **Payme**:
  - `config.ts` — настройки и ссылка на hosted checkout;
  - `merchant.ts` — серверный Merchant API (JSON-RPC).
- `src/features/payments/click.ts` — **только интерфейс Click**. Он всегда выключен
  (`isConfigured() === false`), пока не будут реализованы и проверены callbacks Prepare/Complete
  с реальными тестовыми данными Click.
- Способ оплаты «Онлайн через Payme» появляется в checkout, **только если** заданы
  `PAYME_MERCHANT_ID` и `PAYME_SECRET_KEY`. Сервер отклоняет заказ с этим способом,
  если провайдер не настроен.

### Поток оплаты

1. Покупатель оформляет заказ со способом `payme`. Заказ создаётся со статусом оплаты `unpaid`.
2. На странице заказа кнопка «Оплатить через Payme» отправляет `POST /api/payments/payme/start`.
   Сервер проверяет владельца заказа: вошедший покупатель или гость с токеном из ссылки.
   Затем он перенаправляет на hosted checkout Payme. Сумма всегда берётся из заказа в БД.
3. Payme вызывает `POST /api/payments/payme` (Merchant API):
   - `CheckPerformTransaction` — заказ существует, сумма совпадает до тийина, заказ можно оплатить;
   - `CreateTransaction` — транзакция создаётся, заказ получает статус `pending`;
   - `PerformTransaction` — заказ получает статус `paid`, пишется история, журнал и письмо менеджеру;
   - `CancelTransaction`:
     - до оплаты — `cancelled` (или `failed` при причинах 1–3);
     - после оплаты — `refunded`, если заказ ещё не отправлен и не выполнен, иначе ошибка `-31007`;
   - `CheckTransaction`, `GetStatement` — сверка.
4. Покупатель возвращается на страницу заказа. Статус там читается из БД.
   **Параметры в URL возврата ничего не меняют.**

### Защита

- Каждый запрос Payme проверяется по заголовку `Authorization: Basic base64("Paycom:<PAYME_SECRET_KEY>")`.
  Сравнение идёт за постоянное время. При ошибке возвращается `-32504`.
- Сумма должна точно совпадать с `orders.total_minor`, иначе `-31001`.
- На заказ допускается одна активная или проведённая транзакция. Строка заказа блокируется
  (`SELECT … FOR UPDATE`), чтобы два параллельных `CreateTransaction` не создали две транзакции.
- Повторные вызовы с тем же id транзакции идемпотентны. Повторный `PerformTransaction`
  не проводит оплату второй раз.
- Непроведённая транзакция истекает через 12 часов (43 200 000 мс) и отменяется с причиной 4.
- Протокол сверен с официальным шаблоном Paycom:
  https://github.com/PaycomUZ/paycom-integration-php-template.
  Сайт документации developer.help.paycom.uz был недоступен при разработке: у него истёк
  TLS-сертификат.

## Тестовый режим (песочница Payme)

1. Зарегистрируйтесь в бизнес-кабинете Payme и получите тестовую кассу
   (merchant.test.paycom.uz / песочница test.paycom.uz).
2. В настройках кассы:
   - **Endpoint URL**: `https://<ваш-домен>/api/payments/payme`.
     Payme должен достучаться до сервера из интернета. Для локальной разработки
     используйте туннель, например cloudflared или ngrok.
   - **Поле счёта (account)**: `order_id`. Его значение — номер заказа вида `GR-261121-PTXH`.
3. В `.env.local`:
   ```
   PAYME_MODE=test
   PAYME_MERCHANT_ID=<id тестовой кассы>
   PAYME_SECRET_KEY=<ТЕСТОВЫЙ ключ из кабинета>
   ```
4. Прогоните сценарии песочницы Payme: успешная оплата, неверная сумма, несуществующий заказ,
   отмена до и после проведения, повторные вызовы.
5. **Проверьте формат ссылки hosted checkout в песочнице.** Его не удалось сверить с документацией.
   Сейчас используется `https://test.paycom.uz/<base64("m=…;ac.order_id=…;a=<тийины>;l=ru;c=<return url>")>`.
   Если формат отличается, исправьте `createCheckout` в `payme/config.ts`
   или задайте базовый адрес через `PAYME_CHECKOUT_URL`.

## Переход в production

1. Пройдите merchant onboarding в Payme (договор, проверка) и получите **боевую** кассу и ключ.
2. **Фискализация.** По правилам Узбекистана для чека нужны коды ИКПУ, `package_code`
   и ставка НДС по каждой позиции. Их выдаёт налоговая или бухгалтерия магазина;
   придумывать их нельзя. Когда коды будут в каталоге, добавьте `detail`
   (позиции чека) в ответ `CheckPerformTransaction`. Уточните у Payme, обязателен ли он для вашей кассы.
3. Задайте на сервере:
   ```
   PAYME_MODE=production
   PAYME_MERCHANT_ID=<боевая касса>
   PAYME_SECRET_KEY=<БОЕВОЙ ключ>
   APP_URL=https://<домен>
   ```
4. В боевой кассе укажите Endpoint `https://<домен>/api/payments/payme` и поле `order_id`.
5. Сделайте одну реальную оплату на минимальную сумму и верните её через кабинет Payme.
   Проверьте, что заказ прошёл путь `paid → refunded`.
6. **Смена ключа.** Метод `ChangePassword` намеренно не поддерживается: ключ хранится
   в переменной окружения. После смены ключа в кабинете обновите `PAYME_SECRET_KEY`
   и перезапустите сервер.

## Что не сделано

- Click — только интерфейс, без активной интеграции.
- Сохранённые карты не поддерживаются. Номера карт и CVV сайт никогда не получает и не хранит.
- Позиции фискального чека (`detail`) не передаются — см. пункт «Фискализация».
